# Historical pilot acceptance checklist, design v5

This author-completed checklist predates the independent security audit. Its PASS entries do not establish current acceptance: investigator adjudication, early adjudicator access, ordinary revisions and a private helper leak were found afterward. Re-execute acceptance on the hardened version; see docs/test_runs/V5_REVIEW_AUDIT.md. No deployed acceptance is claimed.

Filled on 2026-10-22 by the build, against the blank checklist supplied with handoff v5 (`docs/design_v5/PILOT_ACCEPTANCE_CHECKLIST_v5_blank.md`, SHA-256 `7dbb9eb4423163aaf59a1c4129c1713179b913bdf6f3686bdae8ab6307ef5665`). PASS, FAIL or UNTESTED with evidence; UNTESTED is not PASS. Every PASS below is an engineering result on synthetic data or on a disposable in-memory database; the investigator's own acceptance session, signature and the `rpc_tlv5_phase('PILOT_SIGNED_OFF')` call are theirs. A Supabase staging project has been created, but credentials and deployed acceptance are not configured and no PostgreSQL server exists on the build machine, so every "Supabase staging" item is UNTESTED and every native PostgreSQL item relies on the hosted CI job.
