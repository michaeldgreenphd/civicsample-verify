## PR review corrections

The review identified reproducibility, pre-context blinding, prediction provenance and analysis-validation defects. Additive migration `0005_review_integrity_fixes.sql` keeps export-access events in the audit log but outside the locked archive, stores packet-problem notes separately from clinical context, rejects post-submission Step 1 amendments at authorization/draft/submission boundaries, and enforces one prediction-set identifier at import and freeze. The loader applies this migration once to both new and existing persistent pilots on startup. The original migrations remain unchanged.

No stored judgments are rewritten. Pre-upgrade packet notes retain their original recorded values and may contain the old context-copy defect; these records require explicit inspection before interpretation. Any previously submitted Step 1 amendment blocks reference use pending a documented investigator disposition. Existing mixed prediction sets cannot be frozen. There is no automatic repair, deletion or reclassification of those records. Restart an already-running local application to apply the upgrade; do not delete its data directory. Export provenance now uses the schema version returned by the database. Archives produced by the older exporter retain their original hashes; repeat downloads from the corrected exporter are deterministic.

Prediction imports and freezes explicitly require READ COMMITTED transactions and serialize on the prediction table. A stale REPEATABLE READ or SERIALIZABLE snapshot is rejected instead of bypassing the single-set check. Rejection paths are tested locally; actual multi-session PostgreSQL concurrency verification remains blocked until a PostgreSQL test service is available.

The analysis validator now verifies export/module/set identity, explicit uncertainty and blinding booleans, and adjudication status/basis semantics. Revision summaries include amendments that preserve decision codes. Trial-level accuracy uses the trial prediction and omits the descriptor-stage four-category exact-match statistic. Implementation versions identify this correction; the v4 CSV format and synthetic fixtures are unchanged. Adversarial CSV tests recompute file hashes to ensure semantic defects are rejected even when checksums match.

Packaging verification also reproduced a local-data leak into Next.js deployment traces once a persistent pilot database existed. Named private/runtime paths are now excluded, and every production build checks its trace against the reviewed SQL inputs (seven with migration 0006) plus compiled/dependency files. CI creates a fictional runtime-file probe before building. The check rejected the unsafe trace and passed after exclusion; no stored database contents were copied into source or committed.

## Additional reference and provenance review

Migration 0006 checks the independent-judgment snapshot again inside the reference-lock transaction, rejects frozen levels with no answers, and refuses a prediction freeze when retained prediction rows belong to a withdrawn case. Rejected operations create no irreversible lock. These checks protect the supplied formal database layer; the application still does not enable formal review. Module B now rejects second final submissions because no authorized amendment workflow is enabled for that optional module. Existing records and migration history remain intact.

The analysis boundary compares shared metadata before joining judgments to predictions, preserves consistent positive case versions instead of substituting version 1, checks adjudicator identity and role, and enforces one case per frame unit. Hash syntax is enforced in both the TypeScript writer and Python reader. The format cannot independently verify a case version against predictions/adjudications because those tables do not carry that field; this limitation is explicit in the analysis notes.

## Frozen contract and adjudication review

Migration 0007 enforces adjudication decision/basis semantics before insertion and checks the selected primary adjudication again before reference locking. It refuses a lock when an existing effective record violates those semantics; correction remains an explicit superseding adjudication, preserving the original. Reference selection follows the pre-unblinding supersession chain, including tied timestamps, and preserves an explicit unresolved decision as null. Multiple primary leaves prevent locking. Before changing the schema, migration 0007 refuses any existing locked formal v4 reference: a corrected view must not silently reinterpret an already frozen export. The transaction rolls back, preserving the old schema and records for explicit investigator migration review. Local synthetic pilot upgrades remain supported.

The migration also blocks new packet versions for frozen held-out cases, binds extension freeze provenance to the retained cases' amendment, and requires every frozen Module B unit to have an answer before its reference can lock. Historical migrations and recorded rows remain intact. These safeguards protect the supplied database layer; formal and Module B review remain disabled in the application.

The analysis validator rejects unsupported Stage C statuses before mapping and requires sampling metadata to remain consistent across each case's determination levels. Equivalent numeric text is accepted through exact decimal comparison. This changes validation, not the export format or any scientific approval.

## Independent audit, migrations 0008–0009, and DB-to-analysis integration

Additive migration `0008_trial_packet_and_concurrency_guards.sql` (`4.0.5-trial-packet-concurrency-guards`) and additive migration `0009_canonical_packet_and_lock_state_guards.sql` (`4.0.6-canonical-packet-lock-state`, bringing the build trace allowlist to ten SQL inputs) resolve the database/contract gaps identified during independent review and follow-up verification while preserving `0008` byte-for-byte from `072bfa0`:

1. **Step-2 trial-context packet freeze (`public.trial_context_packets`)**: Previously, `0007` guarded `evidence_packets` after freeze for held-out cases, but Step-2 `trial_context_packets` could still be inserted, updated, or deleted after freeze, and a held-out `TRIAL_AREA` case could be frozen without a Step-2 `trial_context_packets` row. Migration `0008` attaches `private.trial_context_packets_v4_guard()` and requires `rpc_freeze_v4` to verify `trial_context_packets` presence for every held-out `TRIAL_AREA` case.
2. **Two-step `TRIAL_AREA` design enforcement**: `private.case_levels_v4(p_case_id)` and `private.case_design_v3_v4_guard()` now require `TRIAL_AREA` cases to use `two_step_required = true` (`DESCRIPTOR_LEVEL_IN_TRIAL_CASE` and `TRIAL_LEVEL`), even before a `case_design_v3` row is inserted, and `rpc_freeze_v4` rejects any extraneous `frozen_predictions_v4` levels outside `private.case_levels_v4(f.case_id)`.
3. **Snapshot and formal adjudication concurrency guards (`0008` + `0009`)**: `rpc_snapshot_judgments_v4()` enforces `READ COMMITTED` transaction isolation and locks `cases, assignments, reviews, trial_step1_records, adjudications, judgment_snapshots_v4` in `SHARE ROW EXCLUSIVE MODE`. Additive migration `0009` introduces `private.v4_lock_state` (`SELECT ... FOR SHARE` / `FOR UPDATE` via PostgreSQL `EvalPlanQual`) and updates `rpc_record_adjudication_v3`, `private.adjudications_before_insert()`, `rpc_freeze_v4`, `rpc_lock_reference_v4`, and `rpc_lock_mb_reference_v4` so concurrent `READ COMMITTED` sessions inside `SELECT rpc_...()` portals observe newly committed freeze, reference-lock, and primary-adjudication transitions. Like `0007` and `0008`, `0009` preflight locks `public.reference_locks, public.mb_reference_lock_v4 IN SHARE ROW EXCLUSIVE MODE` under `READ COMMITTED` and refuses any already-locked formal v4 reference, while upgrading persisted databases from either revision of `0008` through the application loader (`getDb()` in `src/server/db.ts`) without resetting pilot data.
4. **Module B adjudication basis validation**: `private.assert_mb_adjudication_semantics_v4()` validates `mb_adjudications_v4` status, decision, basis, and unresolved reason before insertion and before `rpc_lock_mb_reference_v4()`.
5. **Investigator canonical synthetic case authoring RPC (`0008` + `0009`)**: `public.rpc_verify_author_case(p jsonb)` allows an investigator to add synthetic (`SYN-###`) cases (`DESCRIPTOR` or `TWO_STEP` with `trialPacket`) and independent reviewer A/B assignments while pilot review is open. Migration `0009` enforces complete database-side canonical `EvidencePacket` and `TrialPacket` validation using `coalesce(jsonb_typeof(...), '')` to prevent SQL `NULL` bypasses, validating all required string fields, non-empty string arrays (`entryTerms`, `conditions`, `interventions`, `primaryOutcomes`), and nested `{ number, label }` objects in `treeNumbers`, while rejecting non-synthetic IDs, real `NCT` identifiers, and any classifier/blinding keys (including `prompt` and `rubricPrompt`).

The v4 exporter (`src/lib/formal-export.ts`) now connects directly to the database views (`v_independent_judgments_v4`, `v_adjudicated_reference_v4`, `v_frozen_predictions_v4`) and obtains integrity booleans from `rpc_verify_frozen_predictions_v4()` and `rpc_verify_judgment_snapshot_v4()` rather than hardcoded flags. Both the exporter and `analysis/performance_analysis_v4.py` validate `extension_approved_by_amendment` vs `amendment_id` vs `HELDOUT_EXTENSION_APPROVED` records and enforce `unit_type`/`nct_id`/`determination_level` consistency.

The multi-session native PostgreSQL integration suite (`tests/postgres-native.test.ts`) uses the `pg` client and `withDisposablePostgresDatabase()` to create and tear down isolated `verify_disp_...` test databases (never creating tables or modifying rows in the database supplied through `VERIFY_PG_TEST_URL`, and placing the preservation sentinel in its own separate disposable database). It exercises role isolation, negative access, and concurrent freeze vs case withdrawal, freeze vs packet versioning, concurrent review amendments, concurrent formal adjudications, reference lock vs assignment withdrawal, and reference lock vs migration `0008`/`0009` preflight in CI (`postgres:16` service container in `.github/workflows/ci.yml`). Because no local `postgres` or `docker` binary is installed on the macOS build host, the live PostgreSQL test is reported as `BLOCKED` locally and is explicitly distinguished from deployed Supabase JWT/PostgREST gateway verification. Synthetic invite/JWT test scaffolding (`issueSyntheticInvite`, `claimInvitedSession`, `signSyntheticJwt`, `verifySignedJwtClaims`, `revokeActorSessions` in `src/lib/auth.ts`—requiring explicit `aal2` when MFA is required with no default-to-`aal2`, and permanently rejecting revoked JWTs across re-invites; not implemented TOTP/MFA) and administration/approval-gate workflows (`evaluateApprovalGates`, `authorSyntheticPilotCase`, `exportFormalV4BundleForInvestigator` in `src/server/admin-workflows.ts`, plus the served-browser case-authoring workflow) are implemented and tested while keeping formal study activation disabled and all scientific choices (`v1.1` vs `v1.2`, proposed 100-case sample vs 96-case synthetic fixture, `FX_GAIN` `ONEG_CPOS` coverage disposition, rubric, adjudicator, and analysis plan) pending investigator approval.
