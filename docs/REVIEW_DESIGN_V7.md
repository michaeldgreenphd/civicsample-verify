## What design v7 is

One review unit is one (trial, mapping) pair with the study's assignment shown. Both reviewers answer every one of 100 units (56 area, 40 condition row, 4 subgroup), so the review holds 200 initial judgments; the adjudicator breaks ties only; three read-only worked examples (EX7-) sit outside every total. Answers are AGREE, DISAGREE (reason code and note) or CANNOT_TELL with an optional uncertainty flag. The outcome is **clinician confirmation of displayed assignments**; no screen, export or report calls it a positive predictive value or an accuracy. The design documents are copied unchanged into `docs/design_v7/` (the behaviour specification stays in the package because it carries the handoff's synthetic NCT99 placeholders).

## Relation to the existing mapping-confirmation module (migrations 0016 to 0020)

The `mc_*` module served the synthetic pilot that ran on staging on 2026-10-23 (12 synthetic mappings, locked and exported). Design v7 is a separate `mu7_*` module. The supplied migration refuses a v7 design record when a v4, v5 or v6 formal or calibration review exists, but it does not know the `mc_*` module (review finding 3); whether the two may coexist in one database, or the v7 design record must also refuse an `EVALUATION` mapping-confirmation campaign, is a question for the package authors and the investigator.
