# Invited-team deployment plan

This build runs locally with synthetic accounts. Do not publish it as a clinical study service. Formal study import and clinical invitations require a separate investigator decision after a successful pilot.

1. Investigator selects hosting region, retention period, approved study/rubric/sample/version, qualified adjudicator and analysis plan. Record signed approvals privately. Address the known classifier-addition coverage limitation in the target claims.
2. Create a separate Supabase staging project with synthetic records only. Use PostgreSQL 16 compatible behavior. Apply `schema.sql`, then migrations 0002 and 0003 through the migration owner. **Do not apply the local auth shim to Supabase.** Migration 0004 is the isolated local synthetic workflow, not the approved formal study migration.
3. Implement invited Supabase sign-in and token refresh against verified user JWTs, with investigator TOTP/MFA assurance level 2. Disable public self-registration into any study role. Invitations and role assignment must use narrowly authorized administrative tooling; the web process must not hold a service-role key. Production endpoints must call user-JWT RPCs rather than impersonating the local shim's identities.
4. Reconcile the final approved rubric and schemas with the formal import, freeze, snapshot, reference-lock and export user interface. The current app intentionally exposes only the synthetic extension. Connect the implemented synthetic v4 CSV writer to the actual formal database views and test that database output against the analysis program; a standalone fixture passing analysis is insufficient.
5. Run all historical handoff suites against actual PostgreSQL and through Supabase/PostgREST with real reviewer A/B, adjudicator, investigator, outsider and anonymous JWTs. Verify MFA denial, RLS, every view/RPC/table, Step 1 audit payloads, frozen provenance, append-only history, unauthorized exports and unassigned-ID queries.
6. Replace loopback pilot authentication/host restriction with verified deployment-origin validation, TLS and production session handling. Set CSP nonces, remove development unsafe-eval, set secure cookies, enforce rate limits at the gateway and configure no-payload operational logging. Keep previews and analytics from collecting study evidence.
7. Run browser role-isolation and accessibility checks on the staging URL, plus dependency and source leak scans. Test backup restoration, least-privilege database access, revoked accounts, session expiry, recovery procedures, audit retention and data deletion obligations. Keep encrypted backups outside this public repository.
8. Investigator conducts and signs the synthetic pilot checklist. Only after all required gates pass may the investigator authorize a separately reviewed production deployment, private material transfer, formal freeze and clinician invitations.

For a small invited team, managed Next.js hosting plus Supabase is sufficient after these gates; no custom authentication or database cluster is necessary. This plan does not create or pay for services, deploy production or invite anyone.
