## Coverage and limits

- New D4A/D4B observations are required on every membership answer and revision. Other units reject them. Old v7 reason codes and hashes survive the additive upgrade unchanged.
- Reviewer isolation, investigator no-interim access, adjudicator separation, role/MFA checks and locked export access are exercised through the real local SQL lineage.
- Subtype differences do not create membership disagreements or a subtype adjudication task. The exports report separate counts.
- Missing, duplicate, mismatched or altered probability rows/files are refused. The original probability file is retained byte-for-byte; canonical decimal conversion is exact. The binding is immutable and required before a new ONE_PER_TRIAL freeze.
- Bundle mutation checks cover revision coverage, required subtype, invalid reason, external probability overrides, original-file mismatch, metadata/digest mismatch and frozen-binding mismatch.
- Native PostgreSQL: BLOCKED locally; no local server or Docker. The existing hosted PostgreSQL 16 job includes the new 8.1 lifecycle test. Its result is not claimed by this local report.
- Supabase and hosted browser: NOT TESTED for this change. Live practice remains unchanged.
- Full snapshot reauthentication from the exported membership bundle remains limited because intermediate rationale/timestamps are not included. See the engineering contract; passing file checksums is not proof of independent snapshot reconstruction.
