## 4. Review findings on the migration (as a change set; posted on the pull request)

Verified against the file by this review; line numbers refer to `migrations/0024_v7_mapping_units.sql`.

1. **P1, blocking before any staging apply. Audit hash leaks FORMAL answers to the investigator while the phase is open.** Lines 1015 to 1017 hash `assignment_id|revision|answer|reason|note|uncertain|seconds` with no secret; lines 1148 to 1150 write that hash, the unit and the revision into `audit_log`, which the investigator may read at any time (schema.sql policy `audit_log_inv`), and the investigator can read every `assignment_id` from `mu7_queue`. For an AGREE or CANNOT_TELL answer the unknown inputs are the answer (3 values), the flag (2) and a small seconds value, so the hash is invertible by enumeration, and a row that resists is by elimination a DISAGREE. Defeats guard MU7-G50 through the audit channel. Fix: omit `content_sha256` from the audit details (keep it on the row, which RLS hides until the close), or salt it with a value the investigator cannot read.
2. **P2. No serialization between the FORMAL close and in-flight submissions.** `mu7_judgments_before_insert` reads the phase without a lock (lines 1003 to 1006) and the close event is inserted without a lock (lines 950 to 970). Under READ COMMITTED a submission that read OPEN can commit after the close; if the snapshot runs between the two commits, the singleton append-only snapshot no longer matches and guard MU7-G49 refuses every FORMAL export for good. The same unlocked read-then-insert exists between unit import and the freeze (MU7-G11 vs lines 847 to 855). This repository fixed the same class in 0020 (shared lock for writers, exclusive lock for phase transitions). Fix: a transaction-level advisory lock, or `lock table ... in share row exclusive mode`, in the judgment, phase-event, freeze and snapshot triggers.
3. **P2. Cross-design exclusion does not know this repository's mapping-confirmation module.** MU7-G02 (lines 702 to 705) refuses the v7 design only for v4, v5 and v6 reviews; `mc_cases` with `record_category = EVALUATION` and FORMAL rows of the v2/v3 `cases` table do not block it, and the `a00` guard never refuses new `mc_cases` rows. `public.rpc_enroll_reviewer` can still enrol a FORMAL reviewer on the v2 path, bypassing MU7-G08. Question for the package authors and the investigator: should the v7 design record refuse an EVALUATION mapping-confirmation campaign, and vice versa.
4. P3. Phase events have no uniqueness on `event_type` (table lines 215 to 230); MU7-G42's "recorded once" is check-then-insert, so two concurrent `FORMAL_OPENED` calls, or a COMPLETE racing an INCOMPLETE close, both commit. A unique constraint on `event_type` (and a partial unique over the two close types) would make it structural.
5. P3. A PILOT unit can be adjudicated while its reviewers may still revise; a later revision that changes the routing leaves a stale adjudication (unique on `unit_id`, append-only) that `v_mu7_final_reference` reports. PILOT never enters statistics, but the pilot checklist would read a wrong final.
6. P3. `rpc_mu7_freeze` stores an investigator-supplied `queue_sha256` it cannot verify (the queue does not exist yet); a wrong value makes the FORMAL queue unassignable and the singleton freeze cannot be corrected without a migration. Compute the hash from the supplied queue order instead, or warn the operator.
7. P3. Guards MU7-G07, G13 and G60 to G63 live only in the RPC bodies, not in triggers, so a role with direct INSERT (the migration owner; `service_role` where defaults grant it) can insert a unit without a design row or a half queue. Every other guard is a trigger.
8. P3. `rpc_mu7_record_adjudication` inserts the literal mode `PILOT` (line 1655); the trigger overwrites it, so FORMAL rows are stored correctly, but the literal misleads, and an unknown `unit_id` ends as "INCOMPLETE" instead of "unknown unit".
9. P3 (this repository). `private.is_adjudicator()` (0002) is not account-lock aware; 0021 made the other identity helpers honour `account_locks` but not this one, and 0024 depends on it in four policies. Fix belongs in a small repository migration.
10. P3. The header still says NNNN and "0022 or later" in the identical repository copy; the contract pins the file's SHA-256, so the header must stay as is and the contract line is the record of the number assigned (0024). The marker `7.0.0` does not follow this repository's `6.0.x-name` convention; no consumer parses the string.

Categories with nothing to report: every function sets `search_path = ''` and is schema-qualified; RLS is on for all 15 tables with select-only policies; no insert, update or delete grant for `anon` or `authenticated`; private helpers revoked except the four used by policies and views; every MU7-G01 to G63 tag and every named `mu7_*_ck` constraint in the contract exists in the file; no CHECK can evaluate to NULL; append-only and audit triggers cover all 15 tables; queue and judgment uniqueness and the revision chain hold; the cannot-tell routing rule and the three-state export coding match the specification; the four `a00` triggers are pass-throughs until a v7 design is recorded; nothing non-additive (no CREATE OR REPLACE, ALTER or DROP of an earlier object).

## 5. Fixture guard: per-file reviewed identifiers (investigator authorization, 2026-10-23)

`scripts/check-fixtures.mjs` treats every `NCT` followed by eight digits as a real registry identifier. The supplied v7 suite and synthetic pilot carry values of the reserved synthetic NCT99 form, because the migration's own guard MU7-G16 requires a real-format identifier in a FORMAL or worked-example packet, and the supplied v7 checker plants fictitious values in its own negative-control self-test. Under the investigator's constraints the guard now carries an exact list of reviewed values for each of three named vendored files (the v7 suite, the v7 synthetic pilot fixture and the v7 leakage checker): no global NCT99 exemption, no file-wide exemption. Every occurrence in a file is checked against that file's list, an approved value is refused in any other path, a registry-format value in a file name is never allowed, and staged blobs and working-tree files are both scanned as before. Every other leakage rule stays active inside the listed files. `tests/fixture-registry-allowlist.test.ts` pins each of these properties.
